# 2026-09-18：Luna / DeepSeek Flash 长程实跑与 MCP 指引审计

## 结论与证据边界

已使用真实 `gpt-5.6-luna` 和 `deepseek-flash`，通过隔离的 stdio MCP 服务运行内容库中的《失落的凡德林矿坑》与《堕入阿弗纳斯》片段，经历建卡、探索、敌我战斗、存档、恢复与继续行动。实跑发现的服务缺陷已修复，并补充自动回归。**这不是整部战役通关证明，也未达到所有模型都能顺畅自主完成全流程的验收标准。**

内容库当前 46 个包完成完整性检查，共 1,062,815,455 字节；另有 8 个保留历史包。D&D 有 18 份模组归档（包含版本变体），本轮实际覆盖其中两条战役主线，没有把“包可安装”算成“剧情已跑完”。官方文本和完整模型轨迹留在本地隔离目录，不随此报告发布。

本轮使用 CLI 模型客户端验证 MCP；不覆盖 SagaSmith Agent 的 NPC Host worker、真实多人 UI 同时在线、部署域名、HTTPS、真实服务器恢复或正式上线。域名、服务器与生产配置仍按用户要求暂空。

## 已修复的五组问题

1. **工具发现与读取阻塞。** 默认稳定目录保留全部 79 个公开 MCP 工具；旧版动态 exposure 仅在显式兼容配置下启用。修复 Skill 搜索内部 limit=100 与目录最多 20 的冲突。生成参考文档原先只有总表，现在每个 Runtime 工具都有独立标题、说明与输入结构；超长的 module_draft 按 action 拆分，标题带 Markdown 反引号也能读取。保留通用检定和掷骰，没有为 16 工具上限删掉能力。
2. **无意义的阶段阻塞。** Play/Combat 可读取已安装内容包；Combat 可展开当前模组原文；Play 可在既有权限、分支与版本保护下恢复快照。内容包变更仍限制在准备阶段。character_query 的单角色读取及 module_expand 可从资源反查战役，但仍检查跨战役权限。
3. **危险检定与恢复。** character_check 严格校验各 action，避免把错误 skill 字段静默忽略。新增 scene_save：由 DM 对真实模组来源分类，再走既有豁免规则、随机流和幂等回执；包括恐惧条件下的来源特性验证。非法、外部或伪造来源在掷骰前拒绝。战斗期间的 Core relock 现在只能在完整、干净且匹配的检查点上修改 Runtime 指定的版本元数据，不解锁战斗，也不能修改版本规则、出版物、房规等内容。
4. **参数与错误指引。** 明确 inventory_change、角色创建/内容应用、module_query、战斗空间事实、法术付款、休息准备法术、snapshot slot 与 UUID、游戏时钟及版本字段。冲突、未知执行结果和非法参数分别给出恢复方向。模组来源引用要求复制服务器返回的完整对象；法术待裁决不等于效果已生效；未绑定 scene_id 的战斗不算模组验收。
5. **等待时间与测试可靠性。** Skill 去掉必填人数、重复建队、整章预生成、重复读取不可变原文等要求，优先准备当前场景并复用回执。新增 `campaign_query` 的 `payload.detail="summary"`，用于 Agent 恢复长战役；完整 UI 返回保持默认兼容。摘要明确省略项与后续查询入口，避免超长状态被客户端转存到 Agent 无法读取的文件。修复 Windows 模型进程超时只结束包装器的问题，超时结束整棵测试进程树；隔离 MCP home 增加独占锁，防止两个回归实例同时写同一战役。

旧 DeepSeek `*-final` 运行曾与超时后残留进程共享 home，该区间全部排除验收。保留旧轨迹用于定位测试框架问题；后续 `*-clean-continuation` 在清理已核实的测试进程并启用独占锁后运行。清理不涉及用户应用、凭据或业务战役。

实跑期间持续修复服务与文档，因此旧进程不会自动读取最新工具目录/Skill。各轮结果必须按启动时的构建解释；不能将早期错误率当作最终版本错误率，也不能拿不同场景/动作组合计算“优化百分比”。

最终补充了两轮只读复核：四个工具小节在两个模型中均完整可读；测试脚本误写的 `view=bundle` 造成 Luna 一次、DeepSeek 两次失败，归因于脚本，产品正确入口一直是 `resume`。随后针对修复后的摘要，各模型均完成 **3 次调用、0 错误、0 写入**，直接收到可读状态。DeepSeek 同一战役的结构化 resume 从 110,720 字符降到 8,277 字符，get 从 101,644 降到 1,517；这是载荷大小比较，不是端到端耗时对比。

Luna 最后一份只读报告仍自称“真实完成行动数 30”，实际只有三个只读调用；该说法明确排除验收。DeepSeek 将部分真实 null 与省略概念混淆，其结论也须回到原始回执核对。连续性上下文有自己的预算和 `truncated` 标记，摘要并不宣称覆盖全部历史。

## 仍需保留的验收缺口

1. **模型遵循能力。** 两个模型仍出现猜字段、错抄 UUID/校验值、重复读 Skill、把 ad-hoc 战斗当模组进度、把付款回执当效果完成等行为。服务器拒绝非法操作是正确保护；仍需在冻结构建上复跑并核对来源、资源与状态。
2. **完整覆盖。** 本轮不是全部内容库主线通关，也没有覆盖完整 NPC Host 对话、多玩家 UI/Agent 同时写入和部署后的长程恢复。现有权限与并发自动测试不替代这些真实体验证明。
3. **运行环境。** Core 完整测试在 Python 3.12 通过。额外尝试的 Python 3.14 free-threaded 环境暴露既有线程 ContextVar 继承相关测试失败，不能宣称该解释器已通过完整兼容验收。
4. **交付版本。** Core 的新接口已提升为 0.3.1，D&D Runtime 最低依赖同步为 0.3.1，工作区使用本地 editable Core。尚未发布这次 Core 包、推送代码或部署生产；正式分发需要协调发布，不能继续依赖旧版 PyPI 0.3.0。

## 验证与复现

本地证据根目录：`D:/repo/SagaSmith/live-regression-20260918/`。

- `run_model.py`：隔离运行入口；DeepSeek 只在子进程环境中读取本机 Claude 已有凭据，不写入报告或轨迹。
